# Collaboration Model

## Mental model
Each person has an identity and private planning space. People join one or more shared GoalMate spaces. Sharing is explicit; collaboration does not erase personal planning autonomy.

## Task collaboration patterns
### Personal
Visible only in the user's private space unless explicitly moved/shared.

### Shared pool
Visible to the shared space and available for someone to claim. Useful for household chores, errands, project backlog, grocery/needs items.

### Claimed
A member indicates intent/ownership. Claiming should remain reversible and visible.

### Requested / assigned
One person can request another person handle something. Tone and UI should communicate coordination, not command-and-control. Track requester and recipient separately from creator where useful.

### Collaborative
Some work is jointly owned or performed. Do not force a single assignee when the real-world work is shared.

## Lightweight requests
Support low-friction needs such as “pick up Pepsi next time you're at the store” without requiring creation of a heavyweight project-management ticket. Such requests may still normalize to a task/list item under the hood.

## Shared lists and errands
Design the task model so grocery/errand contexts can aggregate relevant shared items. Future context-aware suggestions may use location only with explicit permission and a truthful platform capability model.

## Visibility
Every view/suggestion/search/AI operation must respect space boundaries. Shared dashboards should not reveal private task titles, counts that expose private activity, or private calendar detail without explicit sharing rules.

## Activity
Show useful coordination events (requested, claimed, completed, rescheduled) while avoiding employee-monitoring-style analytics between family members.
