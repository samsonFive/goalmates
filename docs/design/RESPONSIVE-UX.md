# Responsive UX Doctrine

Responsive design here means adapting the **job**, not simply resizing the same dashboard.

## Phone — Capture & Do
Primary jobs:
- quick typed/photo capture;
- see what matters now;
- complete/claim/request tasks;
- check shared errands/lists;
- start/finish focus session;
- opportunity mode;
- lightweight calendar/day view;
- quick ritual check-in/debrief.

Optimize for one-handed/touch use, fast entry, low navigation cost, and useful notifications/deep links when supported.

## Tablet — Plan & Review
Treat tablet as a first-class digital-planner surface, not a stretched phone.

Primary jobs:
- weekly/day planning;
- calendar + task pool together;
- drag/reassign/schedule with accessible alternatives;
- image capture reconciliation with source and extracted items side-by-side where possible;
- family planning/review ritual;
- project review;
- retrospective/learning.

Landscape tablet should be deliberately composed.

## Desktop — Organize & Think
Primary jobs:
- project/workspace depth;
- backlog/Kanban/list/table/calendar views;
- rich notes/research/media/files/decisions;
- bulk organization;
- planning analytics/history;
- account/space configuration;
- capture/reconciliation for larger documents.

## Shared principles
- Same canonical data/domain semantics across form factors.
- Navigation may adapt by device.
- No critical feature should exist only because hover is available.
- Preserve user context when moving between surfaces.
- Test representative widths early and continuously; tablet is not a late breakpoint patch.
