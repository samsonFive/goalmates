# Family Dogfood Acceptance Scenarios

These are product acceptance journeys, not exhaustive UI prescriptions.

## 1. Paper weekly planner → usable plan
A household member photographs a handwritten weekly planner. GoalMates processes it and presents proposed tasks/events. The user corrects one title/date, leaves several tasks standalone, attaches one to an existing project, creates a new project from another, resolves a likely duplicate, accepts the batch, and sees the resulting work in the appropriate personal/shared planning surfaces.

**Pass:** no retyping of the whole page; ambiguity is reviewable; accepted records persist; source provenance remains available.

## 2. Kitchen remodel project
Create/open “Finish Kitchen Remodel.” See outcome/context, open and completed tasks, estimates, participants, progress and rich resources. Add tasks such as paint, shelves, and trim with estimates. Schedule one for after work; complete another; history/progress updates.

## 3. Standalone daily task
Capture “call dentist” without a project. It remains fully functional and does not require a fake project.

## 4. Shared pool and claim
One member adds a household task to the shared pool. Another sees and claims it. Both see the coordination state; completion is reflected without exposing unrelated private work.

## 5. Lightweight request / errand
A member requests “grab Pepsi next time you're at the store.” The recipient can see it in a useful shared/errand context and complete or dismiss/return it according to collaboration rules without navigating a heavyweight PM workflow.

## 6. Plan the afternoon
User has a known end-of-work time and available evening window. They can inspect available tasks with duration/context and place suitable work into the plan/calendar without confusing tasks with events.

## 7. Opportunity mode
User says/chooses “I have 45 minutes.” GoalMates proposes plausible work based on known estimates, schedule and task context. User can optionally indicate energy/mood/context. Suggestions explain enough to be trusted and are easy to ignore.

## 8. Focus session
From a task, start a focus session for a chosen duration. Timer/session state works reliably. On finish, user can mark task complete or leave it open and optionally record progress/actual time.

## 9. Daily debrief ritual
At day end, dashboard surfaces the configured debrief. User sees planned vs completed/moved work, closes or reschedules appropriately, records a lightweight reflection, and the ritual is marked complete.

## 10. Weekly planning/review
A couple/family can review completed work, active projects, outstanding shared requests, next week's calendar/capacity and planning calibration, then commit a realistic week plan.

## 11. Retrospective learning
After enough history exists, dashboard/review can show useful facts such as systematic underestimation or over-planning without shaming the user or rewarding raw task count.

## 12. Project research/context
Inside a project, add formatted notes, image/media/link/file references and a decision. Structured tasks remain accessible alongside the context rather than being buried inside a document.

## 13. Privacy boundary
A user has private tasks and shared household tasks. Another household member cannot retrieve private titles/details through dashboards, search, activity feeds, duplicate matching, suggestions, URLs, or AI-assisted features.

## 14. PWA/device behavior
Install the app from a supported mobile browser. Core flows remain coherent at phone, tablet portrait/landscape, and desktop widths. Tablet planning is deliberately useful rather than a stretched phone layout.

## 15. Failure honesty
Vision/AI provider is unavailable. Uploaded capture remains safe, status reports failure truthfully, retry/manual-entry options exist, and the app never fabricates extracted tasks.
